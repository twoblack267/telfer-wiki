## 3. Data Model Redesign

### 3.1 New `people.json` Schema (Per Person)

```json
{
  "id": "string",                    // unique slug: "john-telfer-1731"
  "slug": "string",                  // URL-safe: "john-telfer-1731"
  "first_name": "string",
  "middle_name": "string|null",
  "last_name": "string",             // birth surname (maiden for women)
  "married_name": "string|null",     // if different from last_name
  "birth_year": "number|null",
  "birth_year_display": "string",    // "1731", "c.1731", "~1731"
  "death_year": "number|null",
  "death_year_display": "string",    // "1895", "living", "c.1847"
  "display_name": "string",          // "John Telfer (1731–?)"
  "title": "string",                 // page title
  "tags": ["bio","family","person","ancestor","immigrant","adopted","spouse"],
  "confidence": "high|medium|low",   // for unproven connections
  "is_living": "boolean",            // derived: birth>=1940 && death=null
  "generation": "number",            // 1=root, 2=children, etc. (from root)
  "branch": "telfer|parker|lawrie|baker|provis|masters|wright|husband|wife|other",
  "relationships": [
    {"type": "Self", "names": ["John Telfer"]},
    {"type": "Spouse", "names": ["Elspeth Young"], "marriage_year": 1750},
    {"type": "Father", "names": ["Parent Name"]},
    {"type": "Mother", "names": ["Parent Name"]},
    {"type": "Children", "names": ["Child1", "Child2"]},
    {"type": "Siblings", "names": ["Sibling1", "Sibling2"]}
  ],
  "parents": ["parent-slug-1", "parent-slug-2"],
  "children": ["child-slug-1", "child-slug-2"],
  "spouses": ["spouse-slug-1", "spouse-slug-2"],
  "siblings": ["sibling-slug-1", "sibling-slug-2"],
  "related_trees": ["telfer-main", "parker", "lawrie", "baker-march-webster", "sporer", "cullen", "ivory", "virgen"],
  "vault_file": "string",            // source vault filename
  "images": [{"src": "images/people/...", "alt": "...", "caption": "..."}],
  "person_photo": "images/people/...",
  "body_markdown": "string|null",    // NULL for living people (privacy)
  "body_stripped": "string|null"     // NULL for living people
}
```

### 3.3 Privacy Sanitization Rules (Updated)

```javascript
function sanitizePerson(person) {
  if (person.is_living) {
    return {
      ...person,
      body_markdown: null,
      body_stripped: null,
      children: [],
      spouses: [],
      siblings: [],        // or keep siblings? decision needed
      images: [],          // no photos of living people
      person_photo: null,
      relationships: person.relationships.filter(r => r.type === 'Self'),
      // KEEP: id, slug, display_name, birth_year_display, generation, branch
    };
  }
  // For deceased: if they are parent/grandparent/great-grandparent of living,
  // keep full data. If more distant, full data OK.
  // Actually: "Publish up to great-grandparents of living" means:
  // living person → parents (gen N-1) → grandparents (N-2) → great-grandparents (N-3) = KEEP FULL
  // great-great-grandparents (N-4) and beyond = KEEP FULL (no restriction)
  return person;
}
```

## 5. Tree Rendering Overhaul

### 5.1 Current Renderer (Discard)
- `src/pages/people/full-tree.astro` uses hardcoded `GENERATIONS` array
- Linear left-to-right, one person per generation
- Generation-jump buttons for 8 fixed generations
- Cannot handle: multiple children, multiple spouses, lateral branches

### 5.2 New Renderer Requirements

**Architecture:** Recursive component tree with virtualized rendering

```
<FullTree>
  <TreeRoot rootSlug="john-telfer-1731" />
</FullTree>

<TreeRoot>
  → finds root person
  → renders <PersonNode person={root} depth={0} isRoot={true} />
</TreeRoot>

<PersonNode>
  → renders person card (photo, name, lifespan, spouse chips)
  → finds spouses → renders <SpouseRow spouses={spouses} />
  → finds children → renders <ChildrenRow children={children} />
  → handles collapse/expand via <details> (already working)
  → handles generation-jump via scrollIntoView
</PersonNode>

<SpouseRow>
  → horizontal chip row: [Spouse Name (years)] [m. YYYY]
  → click → scroll to spouse's PersonNode (may be in different branch)
</SpouseRow>

<ChildrenRow>
  → vertical stack of <PersonNode> for each child
  → each child renders their own subtree recursively
  → handles multiple children (horizontal layout with connectors)
</ChildrenRow>
```

### 5.3 Key UI Features

| Feature | Implementation |
|---------|----------------|
| **Multi-branch layout** | Recursive children rows; horizontal for siblings, vertical for generations |
| **Connector lines** | CSS-based (SVG or ::before/::after) between parent→children, spouse↔spouse |
| **Generation jump** | Replaced by: **Branch selector** (Telfer/Parker/Lawrie/etc.) + **Person search** (typeahead) |
| **Person cards** | Compact: photo, name, lifespan, spouse chips, expand toggle |
| **Spouse navigation** | Click spouse chip → scroll to spouse's node (cross-branch) |
| **Mobile** | Horizontal scroll on tree container; cards `min-width: max-content` |
| **Privacy** | Living cards show name only, no expand, no children, "Living — details private" badge |
| **Confidence badges** | 🟢 High / 🟡 Medium / 🔴 Low on person cards |
